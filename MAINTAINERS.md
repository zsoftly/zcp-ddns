## Becoming a maintainer

The path is: contributor, then triage access after a few merged PRs, then maintainer with write access when the track record supports it. Maintainers are invited by the existing maintainers and ZSoftly.

## Maintainer duties

- Review pull requests according to the review target in [CONTRIBUTING.md](CONTRIBUTING.md)
- Triage new issues and keep labels current
- Keep CI green on `main`
- Record decisions in GitHub issues, not in chat

## Handing over

Maintainership is voluntary. A maintainer can step down at any time:

1. Announce it in an issue and, where possible, nominate or help onboard a replacement.
2. Reassign or hand off any open PRs and claimed issues to the remaining maintainers.
3. Move your entry to the emeritus list. Write access is removed; the contribution history and credit remain.

Keep `.github/CODEOWNERS` in sync with the current maintainer list whenever it changes.
